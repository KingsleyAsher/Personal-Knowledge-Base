# 跨盘回收修复 · 2026-11-04

旧实现将目录从资料库直接 `rename` 到服务私有目录。当资料库和服务状态目录分处不同卷时，Windows 返回 `EXDEV`；通用错误映射显示为 `RESULT_UNKNOWN`。同一原语也影响旧目录回收项的恢复。

新回收项保存在资料库自身的 `.kbmeta/desktop-trash/<id>`，与资料库处于同卷，仍处于内部元数据目录，不加入普通文件树。服务操作凭据及回执继续保存在原服务私有目录。列出、预览、恢复、永久删除和恢复回执均兼容旧服务目录中的回收项。

旧目录回收项跨盘恢复时，先复制到资料库卷上的内部暂存目录，逐项检查目录、文件 SHA-256、数量和链接限制，再在该卷发布到目标；原回收副本保留，行为与旧单文件恢复的保留策略一致。目标已存在时拒绝覆盖。不采用未经验证的“复制后删原件”来绕过错误。

旧失败回收操作若仍处于 prepared，只有确认回收原目录不存在、源目录与所有后代修订均匹配原意图时，才能将回执标为已失败；不自动重新执行回收。证据不满足时保留 unknown。

验证使用隔离示例资料：真正分处 D、C 两卷，先复现原 rename 的 EXDEV，再验证新目录回收、子文件预览、空目录与原字节恢复、目标冲突拒绝、旧回收目录跨卷恢复、永久删除、失败回执核对及外部编辑时保留 unknown。原有服务文件生命周期简查通过。最终已安装程序也在隔离双卷示例库完成“创建目录与文件—回收—预览—恢复”检查。
