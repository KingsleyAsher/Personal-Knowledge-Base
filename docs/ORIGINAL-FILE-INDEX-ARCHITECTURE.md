# 原件索引架构

插件 2.5.3、独立客户端 1.1.1 的发布实现（初次本地交付为 2.5.0 / 1.1.0）。程序升级不等于资料库已迁移；用户须在对应资料库预览并确认。

## 两端入口

- DSH 插件：个人知识库设置 → 索引架构迁移与版本 → 迁移到索引架构。
- 独立客户端：左下角设置 → 迁移到索引架构。完整设置中也有同名入口。
- 两端使用相同的共享内核和资料库身份。客户端迁移不依赖 DSH 在线；插件迁移不依赖客户端运行。两端同时连接同库时共用文件目录、分类和检索索引，服务保持单一写入者。

## 数据模型

原件保留在当前资料库中的真实位置。`索引层/文件目录.json` 保存文件身份、相对路径、内容指纹、分类、标签和可用状态，不保存正文副本。`索引层/全文/` 保存可重建的全文检索数据，向量检索继续使用已有的 `索引层` 存储与模型配置。

按原件自身的 frontmatter、所在目录建立初始分类；用户可在“真实文件分类”中修改分类，修改只写文件目录。分类界面可筛选文件路径、分类、类型和标签。原件既有正文、文件名和目录不因此改变。

对已经整理的原件，迁移继承其旧自动引用条目的分类目录、类型与标签，避免把按日期存放的归档目录误当成知识分类。原件明确填写的 category 和用户手工分类优先。客户端左栏的“原件分类”按这些索引分类列出真实原件，点击打开原件本身；“文件目录”继续展示物理位置，并显示原件分类标识。

分类规则第 2 版将存储位置和主题分开：去除旧目录编号、日期、归档路径和任务 ID；优先使用手工分类与原件明确分类，再根据名称、标签和有意义的目录线索建立主题。证据不足的资料放入“待分类”，不据此宣称已经阅读或理解正文。客户端按主题逐层展开，例如“学习与课程 → 数学分析”。

解析底稿和知识库请求、导航等管理文件保留在目录中，原件分类默认不显示，可通过浏览范围切换查看。普通 JSON 原件不会仅因扩展名而隐藏。“重新整理主题分类”只更新文件目录元数据，先备份旧目录到索引层分类历史，保留手工分类，不修改原件。

迁移预览、文件分类和分类浏览均分页传输，过滤发生在分页之前。完整扫描、指纹和旧引用清单留在服务端；页面不会一次接收整库清单，避免触发共库协议的 1 MiB 响应帧上限。读取状态失败时显示错误与重试入口，不把未知状态显示为“尚未迁移”。

既有 `.kbmeta` 中的库身份、权限、备份与服务事务记录继续保留和使用。本版没有把这些运行元数据全部搬入索引层；“索引层”指文件目录、分类、全文和向量等检索派生数据。迁移不创建标准业务目录、规则文件或模板，也不清除用户原有的这些文件。旧目录补齐功能保留为明确标注的可选项，不是架构迁移。

## 迁移与读取

预览只读取资料和必要元数据，列出真实文件与识别的旧自动生成引用。确认时重新核对库身份、分类版本和文件指纹；原件在预览后变化、原件缺失、路径链接或扫描不完整时拒绝发布。原件缺失不能用旧引用中的缓存正文替代。

完整文件目录的原子发布是切换点。随后重建全文索引；如果索引构建失败，明确返回“文件目录已启用、索引待完成”，不报告全部完成，用户可处理原因后刷新。原件与旧索引保持原样。再次确认已有目录会核对并更新目录，不创建第二份原件。

识别出的旧机器引用保留在原处，但不再作为独立知识或正文检索。用户自己写的摘要和笔记仍是独立真实文件，不因包含 source 字段而被当成机器引用。原地接入及收件箱分类在新模式下登记原件，不再生成分类正文副本；显式复制导入仍会按用户选择复制原件。

文本、代码等可读文件建立全文索引，检索结果及读取定位指向真实文件。PDF、图片、音视频等二进制资料会登记身份和分类；本次迁移不自动执行 OCR/ASR，不据此宣称这些文件正文已经可检索。已有解析功能和权限仍按原流程管理。

## 文件变化与边界

维护与“刷新文件与索引”会重新核对文件。改名可在同一文件系统身份及内容指纹唯一匹配时保留分类；无法核对的跨盘移动或复制不会猜测为同一文件。缺失文件保留缺失状态，检索不使用其旧正文作当前证据。文件目录是派生数据，包含用户手工分类，应随正常备份保留。

已有隐私分区及排除策略继续生效；画像、人物类型和私密旧引用的分类会保护对应原件。管理接口需要实际管理授权，普通模型调用不能通过参数自报管理员。文件目录只授权当前库内的普通文件，不因 source 字段或目录链接获得库外访问权限。

验证使用隔离合成资料。真实私有库迁移、真实模型回答、全部二进制解析质量、大库性能和跨设备文件身份匹配不由这些检查证明。
