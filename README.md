# 个人知识库（Personal Knowledge Base）

> **产品愿景（原作者原话，原文保留）**
>
> 一个个人的知识库，它可以记录你的性格、做事方式和你所有的资料，并帮你有序的归档整理，并带有一个专门用于管理与对话的Agent。你可以随时向他提问，查资料等等，它会根据你的习惯与你规定的方式进行回答。你能够掌握全局资料给你更全面更好的答复与建议。

---

## 一、这个仓库里是什么

一个 **DSH（DeepSeek Harness）桌面版插件**：`@local/dsh-knowledge-base`。

它给宿主加三样东西：

1. **7 个知识库工具**（见第五节）—— 让 Agent 能读写、检索、自检一个**本地 Markdown 知识库**；
2. **设置页「个人知识库」** —— 选目录、识别目录类型、建库/接入/导入、看导入进度；
3. **顶栏页签** —— 浏览当前库的分类与文件清单（隐私分区只给数量）。

当前版本：**`0.1.0-p8`**，构建 ID **`fd875c77c36e09ba`**（由 10 个装载文件的 sha256 汇总而成，见第七节）。

## 二、现在**不**包含什么（先读这段，别误会）

| 你可能以为 | 实际情况 |
|---|---|
| 装完就有一个「知识库管家 Agent」 | **没有。** 人设与作业流程属于 **agent 预设层**（profile 配置），不随插件包分发。装完得到的是**能力**（工具），不是**那个人**。 |
| 装完就有一个装满资料的知识库 | **没有。** 不含任何知识库内容，库里放什么、怎么分类，取决于你自己和你给的目录。 |
| 装完会有向导带你走 | **没有引导。** 需要自己进「设置 → 个人知识库」，按第四节三步走。 |

> 换句话说：这个仓库卖的是「手」，不是「人」。要实现愿景里那句「带有一个专门用于管理与对话的 Agent」，还需要一层预设（人设 + 技能 + 工具行）——那是后续版本要解决的事，当前未做。

## 三、安装

本插件只针对 **DSH 桌面版**验证过（`profiles/desktop`）。桌面版 profile 由 Electron 应用独占管理，**不能**用命令行 `dsh plugin add` 安装——只能从应用的插件管理界面装。

1. 打开桌面版 → **设置 → 插件**，安装本地包（或用本仓库源码 `npm pack` 出 tgz，见第七节）；
2. 装完**必须完全退出应用（含系统托盘图标）再打开**——插件行只在 profile 启动时读入，只关窗口不算退出；
3. 重开后进「设置 → 个人知识库」，能看到状态块（知识库路径 / 条目数 / 构建号）即为装好。

包内 `cordis.patch.yml` 在加载时只会自动插入一行 `kb-core`（插件本体），**不会**改动宿主的其他任何配置。

## 四、首次使用（三步）

1. 进「设置 → 个人知识库」；
2. 在「待处理的文件夹」里选一个目录 —— 点 **「选择知识库文件夹」**（或直接粘贴路径）；
3. 点 **「自动建库 / 识别」**，由服务端自己判断该怎么处理：

| 你选的目录 | 会发生什么 |
|---|---|
| 空目录 | 建一个标准库（按 `categories` 建分类目录，不建空壳文件） |
| 已经是本插件的库 | 直接接入，不覆盖任何既有文件 |
| 普通资料文件夹 | 先识别结构（文件数/目录数/可写性），再按分类导入 |

**要点：选目录只记录候选，不绑定、不切换、不改动它**；只有点第二个按钮才会真正执行一次判断与动作。重复导入同一来源不会重复建条目（按来源 + 相对路径去重）。

取消选择不会改变当前绑定；正在跑的导入可以随时取消，取消后原库绑定保持不变。

## 五、7 个工具

| 工具 | 用途 |
|---|---|
| `kb_status` | 看状态：绑定的库、条目数、索引健康、构建号、状态目录 |
| `kb_bind` | 绑定 / 切换知识库目录（原子提交，提交前会核对配置版本与目标库身份） |
| `kb_init` | 初始化或补齐一个库的分类目录与索引（幂等） |
| `kb_record` | 写入或更新一条条目（**更新必须带 `entryId` + `expectedRevision`**，版本不符返回 conflict 且不改文件） |
| `kb_search` | 检索（索引层 + 正文全文；索引失效会自动回退扫描磁盘） |
| `kb_check` | 自检：孤儿条目、死链、frontmatter 缺失、索引陈旧；`rebuild` 可重建索引 |
| `kb_import` | 导入外部资料（plan / run / status / cancel；attach 接入原目录或 copy 复制进收件箱） |

## 六、配置项（`cordis.patch.yml`）

装好之后这些都在插件配置里，一般不用手改。

| 字段 | 默认 | 说明 |
|---|---|---|
| `kbPath` | `''`（未绑定） | 知识库根目录。留空 = 首次进设置页时再定 |
| `stateDir` | `''` | 插件状态目录（`config.json` / `binding.json` / 索引 / 日志 / 自检报告）。留空 = 按 profile 自动隔离为 `<profile>/kb-state` |
| `categories` | `00-画像` … `90-收件箱` | 初始化时创建的分类目录（只建目录，不建空文件） |
| `privateDirs` | `00-画像`、`30-人物关系` | **隐私分区**：清单与地图里只给数量，不列文件名 |
| `excludeFromSearch` | `.kb`、`.kbmeta`、`50-底稿`、`90-收件箱`、`00-知识库请求通道`… | 不参与检索的目录（工具、原始材料、加工件） |
| `followLinks` | `false` | 库内链接/重解析点是否允许写入；`false` = 一律拒绝 |
| `logLevel` | `info` | `debug` / `info` / `warn` |

## 七、构建、验收与目录结构

### 打包

```bat
npm.cmd pack
```

包内只含 `src/`、`cordis.patch.yml`（以及存在时的 `README.md`）。本仓库的 `tests/` 与 `LICENSE` **不算装载文件**，不影响构建 ID。

### 构建 ID 的口径

由下列 **10 个文件**的 sha256 汇总（`相对路径 + \0 + sha256` 逐行拼接后再取 sha256，前 16 位）：

```
package.json
cordis.patch.yml
src/host/index.js      src/host/kbcore.js    src/host/fsindex.js
src/host/importer.js   src/host/import-service.js
src/host/map.js        src/host/selftest.js  src/client/index.js
```

所以「版本号」可以自称，**构建 ID 不能**——文件内容不同，ID 必不同。运行态里设置页「构建」一行显示的就是它。

> 注：git 会把文本文件的换行统一为 LF（Windows 检出时才转回 CRLF），所以**直接拿克隆目录算哈希可能与发布包不一致**。要对齐发布包，请以 `npm.cmd pack` 产出的 tar 包内容为准。

### 自检测试

```bat
node tests/directed-f1f4.mjs        :: 22 项：更新契约 / 隐私反例 / 提交并发
node tests/directed-r1r7.mjs        :: 75 项：R1–R7 定向回归
node tests/independent-import-counters.mjs   :: 17 项：导入计数独立反例
node tests/label-no-numbering.mjs   :: 设置页按钮文案闸门（禁序号 ①–⑳）
```

说明：这些套件是在 Windows + DSH 桌面版上实测通过的（p8：22/22、75/75、17/17），部分断言绑定 Windows 路径行为；在别的平台上跑可能需要对路径判据做调整。它们都应在**独立临时目录**里跑，不要指向你的真实知识库。

### 目录结构

```
├─ package.json          插件清单（main / exports / dsh.bundle.patch）
├─ cordis.patch.yml      装载行（唯一会自动插入宿主的配置）
├─ src/
│  ├─ host/              宿主半边：工具、核心、索引、导入、地图、自检
│  └─ client/            客户端半边：设置页与顶栏页签
└─ tests/                定向回归（不随包分发）
```

## 八、隐私与安全

- **全部本地**：宿主侧不发起任何外部网络请求；客户端唯一的请求是同源的本机接口 `/kb-core/api`（插件自己注册的）。没有遥测、没有上报。
- **隐私分区遮罩**：`privateDirs`（默认 `00-画像`、`30-人物关系`）命中的内容，在清单/地图/最近变更里**只给数量与体积，不出现文件名与正文**。
- **状态不落工作目录**：默认写在 `<profile>/kb-state`，不会把配置、索引、日志散落到你当时的工作目录。
- **写入是谨慎的**：更新必须带版本号（`expectedRevision`），版本不符直接拒绝不改文件；写前自动备份；`update` 失败**不会**退化成 `create`（避免绕过冲突）。
